Claude Code 日常技巧精選

從社群上百個技巧中精選出每天都用得到的，按情境分類。每一條都很短，挑有感的先用。

📝 提問與交辦

  • 說目標，不只說步驟：講出任務背後的意圖（「使用者反映結帳很慢」），Claude 會做出比逐步指令更好的判斷。
  • 一次給齊規格：把需求、限制、驗收標準在第一句話講完，比擠牙膏式追加修改省一半 token 和時間。
  • 貼錯誤訊息全文：不要描述錯誤，直接貼 stack trace 全文。
  • 貼截圖：UI 問題直接拖圖片進終端機，Claude 看得懂畫面。
  • 用 @檔名 精準指路：知道問題在哪個檔案就直接指名，省掉它自己摸索的時間。

🧠 上下文管理

  • 一個任務一個對話：換主題就 /clear，混在一起品質會掉。
  • 在長任務前先 /compact：別等上下文爆了才壓縮。
  • 給 /compact 指示：「壓縮時保留資料庫 schema 的討論」可以控制留下什麼。
  • CLAUDE.md 保持精簡：它每次對話都載入，肥大的 CLAUDE.md 就是長期的上下文稅。
  • 大範圍搜尋交給 subagent：「用 subagent 找出所有用到這個 API 的地方」，主對話只收結論。

⚙️ 流程與自動化

  • 複雜任務必走 Plan Mode：Shift+Tab，先看計畫再放行。
  • 格式化交給 hooks：PostToolUse hook 自動跑 formatter，從此不用提醒。
  • 重複的流程存成 skill：調教好的工作流（如「發布版本的標準步驟」）存成 skill，下次自動套用。
  • 常用核可寫進權限白名單：在 settings.json 允許 npm test、git status 這類安全指令，減少打斷。
  • 用 ! 直接跑指令：! npm test 的輸出會進入對話脈絡，比自己貼結果快。
  • 讓它寫 commit：Claude 看得到完整 diff，寫的 commit 訊息常比你自己寫的完整。

✅ 驗收與品質

  • 要求證據：「跑測試並貼出輸出」「截圖給我看」——看證據比口頭「完成了」可靠。
  • 讓它自我檢查：做完後問「重新審視這段修改，有沒有遺漏的邊界情況？」常能抓到問題。
  • 用乾淨的眼睛審查：開新對話（或 subagent）審查剛寫好的程式碼，避免「自己改自己看」的盲點。
  • 小步提交：每完成一個邏輯單位就 commit，出問題容易回滾。
  • 看到不對勁立刻 Esc：打斷加修正，永遠比走完錯路便宜。

🚀 進階一點

  • git worktree 平行開工：多個工作副本各跑一個 Claude，互不干擾。
  • headless 模式進 CI：claude -p "檢查這個 PR 的安全問題" 可嵌進自動化流程。
  • 把常見問答寫進 CLAUDE.md：發現 Claude 重複犯同一個錯，就把正確做法寫進 CLAUDE.md，從此根治。
  • 連按兩下 Esc 回溯歷史：回到先前的訊息重新編輯，分岔出不同方向。
