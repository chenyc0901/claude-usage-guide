Hooks、Subagents 與上下文進階

這三組功能是「會用」和「用得好」的分水嶺——它們把 Claude Code 從一個助手，變成可靠的自動化系統。

1. Hooks：100% 確定性的自動化

提示詞是「機率性」的——Claude 大多會照做，但偶爾會忘。Hooks 是「確定性」的——在指定事件發生時必定執行你的 shell 腳本，沒有例外。適合放鐵律：

  • 每次改完檔案自動跑 formatter / linter
  • 阻止任何碰 .env 或 production 設定的操作
  • 任務結束時發通知

常用事件：PreToolUse（工具執行前，可攔截）、PostToolUse（執行後）、SessionStart、Stop。設定在 settings.json：

// .claude/settings.json — 改完檔案自動格式化
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write \"$CLAUDE_FILE_PATHS\"" }
        ]
      }
    ]
  }
}
💡 判斷法則：「希望它做」的事寫在 CLAUDE.md；「絕對必須做／絕不能做」的事做成 hook。

2. Skills：把調教好的流程存起來

Skill 是一個資料夾加一份 SKILL.md，描述一個可重用的工作流。Claude 平常只看到它的一行簡介，情境符合時才載入完整內容——所以不佔上下文。

# .claude/skills/release/SKILL.md
---
name: release
description: 發布新版本的標準流程
---

1. 確認所有測試通過（npm test）
2. 更新 CHANGELOG.md 與版本號
3. 建立 git tag 並推送
4. 在 GitHub 建立 release，附上變更摘要

使用時機：你已經教過 Claude 一次怎麼把事情做對（格式、步驟、標準），不想每個新對話重教一遍——存成 skill，之後自動套用。也可以打 /skill名稱 手動觸發。

3. Subagents：平行子代理與上下文保護

Subagent 是有獨立上下文的子代理。兩大用途：

  • 保護主對話上下文：「用 subagent 搜尋整個 codebase 找出所有呼叫這個 API 的地方」——子代理讀了幾十個檔案，主對話只收到結論。
  • 平行作業：把互相獨立的子任務（讀多個檔案、跑多組測試、查多個來源）同時派給多個 subagent，大型任務甚至可由數百個平行子代理協作（Dynamic Workflows）。

可以在 .claude/agents/ 定義自訂 subagent（指定它的角色、工具與模型），例如一個只負責 code review 的審查代理。經驗法則：支線與可平行的工作交給 subagent；單檔閱讀、循序的工作自己做。

4. 上下文工程（Context Engineering）

把上下文當成預算來經營：

  • 常駐成本最小化：CLAUDE.md 精簡、MCP 伺服器只開會用到的（每個都佔工具定義空間）。
  • 大量輸入隔離：探索、搜尋、讀大檔案走 subagent。
  • 定期釋放：/compact 帶指示壓縮；任務切換就 /clear。
  • 長期記憶外部化：跨對話要記住的事寫進 CLAUDE.md 或筆記檔，讓 Claude 自己維護一份「學到的教訓」文件效果很好。

5. 組合技：一個可靠的自動化系統長這樣

  1. CLAUDE.md 定義專案知識與驗收標準（要求附證據）
  2. Hooks 把 format、lint、敏感檔案保護做成鐵律
  3. Skills 收錄發布、review、除錯的標準流程
  4. Subagents 處理探索與平行工作，主對話保持乾淨
  5. 複雜任務一律 Plan Mode 先對齊，再放行執行
