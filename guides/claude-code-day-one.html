第一天就該知道的事

這些是許多人用了好幾週才發現、然後說「早知道就好了」的功能。第一天看完，少走幾週彎路。

1. Shift+Tab 是最重要的快捷鍵

它在三種模式間切換：一般模式（每個動作問你）→ 自動接受編輯（改檔案不再逐次確認）→ Plan Mode（只研究和規劃、不動手）。新手最常見的錯誤是讓 Claude 在沒對齊方向前就開寫——複雜任務先進 Plan Mode。

2. Esc 不是放棄，是方向盤

  • 按一下 Esc：打斷正在進行的動作。看到它走錯路，立刻打斷加修正，比讓它走完便宜得多。
  • 連按兩下 Esc：打開訊息歷史，可以跳回先前任何一句話重新編輯，從那個時間點分岔重來。

3. 引用檔案和執行指令有專門語法

  • @src/auth.ts —— 在訊息中精準引用檔案（有自動補全），比讓它自己找快。
  • ! npm test —— 開頭加 ! 直接執行 shell 指令，輸出自動進入對話脈絡。
  • 直接把圖片拖進終端機 —— 設計稿、錯誤截圖它都看得懂。

4. /init 是新專案的第一個指令

進到任何專案先跑 /init，讓 Claude 掃描程式碼並產生 CLAUDE.md。之後發現它重複犯同樣的錯（用錯套件管理器、忘記跑 lint），就把規則加進 CLAUDE.md——這比每次口頭提醒有效得多。

5. 對話不是越長越好

上下文（context）用量越高，輸出品質越差。換任務就 /clear 開新對話；長任務中途用 /compact 壓縮歷史。把「對話」當成暫存記憶，把「CLAUDE.md」當成長期記憶。

6. 權限提示可以馴服

一直跳出「允許執行嗎？」很煩，但別直接開最寬鬆模式。正確做法是把你信任的指令（npm test、git diff 這類唯讀或安全操作）加進 .claude/settings.json 的允許清單，危險操作保留確認。

7. 讓它做完整任務，而不是一行一行問

Claude Code 的強項是「自主完成完整任務」：給它一個 bug 報告，它會自己重現、定位、修復、跑測試。把它當成隊友交辦任務，而不是當成自動補全工具一行一行問。

8. 它可以操作 Git，而且做得很好

「commit 這些修改」「開一個 PR」「看一下這個 PR 的 diff 幫我 review」「找出這個 bug 是哪個 commit 引入的」——全部可以直接交辦。Claude 看得到完整 diff 與歷史，寫的 commit 訊息通常很完整。

9. 卡住先問 /doctor 和 /help

環境怪怪的（登入失效、MCP 連不上）先跑 /doctor 自我檢查；忘記有什麼指令就 /help。

10. 第一週的合理期待

  • 它會犯錯——所以才需要 Plan Mode、小步提交和證據驗收。
  • 它的輸出品質高度取決於你給的脈絡品質——投資在 CLAUDE.md 和清楚的任務描述上，回報最大。
  • 信任是漸進的——從小任務開始，熟了之後再交辦大型重構。
