Slash 指令完整參考

在 Claude Code 對話框輸入 / 就會列出所有可用指令。這頁按用途分類整理每個指令的用法；版本更新很快，最權威的清單永遠是你終端機裡的 /help。

💬 對話與上下文管理

指令用法
/clear清空對話歷史，開始全新任務。換主題時必用，避免舊脈絡干擾。
/compact [指示]把對話歷史壓縮成摘要，釋放上下文空間。可加指示控制保留什麼，例如 /compact 保留 API 設計的討論。
/context視覺化目前上下文的使用狀況——哪些東西（系統提示、工具、MCP、對話）各佔多少 token。
/rewind回溯到先前的檢查點（checkpoint），可以只還原對話、只還原程式碼、或兩者一起。改壞了想反悔時用。連按兩下 Esc 也能開啟。
/resume列出過去的對話，選一個接著聊。終端機關掉了也找得回來。
/export把目前對話匯出（複製到剪貼簿或存成檔案），方便分享或留檔。
/cost顯示本次 session 的 token 用量與費用統計（API 計費使用者）。
/usage查看訂閱方案（Pro / Max）的用量額度還剩多少。

📁 專案與個人設定

指令用法
/init掃描專案結構，自動產生 CLAUDE.md 專案說明文件。每個新專案的第一個指令。
/memory開啟編輯器修改 memory 檔案（專案的 CLAUDE.md 或全域 ~/.claude/CLAUDE.md）。也可以在訊息開頭打 # 快速把一條規則存進 memory。
/config開啟設定介面：主題、回應風格、通知等。
/model切換模型，例如 /model opus。複雜任務換強模型、簡單任務換快模型。
/permissions檢視與編輯權限規則——把信任的指令（如 npm test）加進允許清單，減少確認彈窗。
/add-dir <路徑>把另一個資料夾加入工作範圍，讓 Claude 同時操作多個專案目錄。
/hooks互動式設定 hooks（工具執行前後自動跑的腳本），不用手寫 settings.json。
/agents建立與管理自訂 subagent（子代理）——定義它的角色、可用工具與模型。
/output-style切換輸出風格（簡潔／詳細解說等），也可建立自訂風格。
/statusline自訂終端機底部的狀態列顯示內容。
/vim開啟 vim 編輯模式，輸入框支援 vim 按鍵。
/terminal-setup設定終端機按鍵綁定，讓 Shift+Enter 可以換行（iTerm2 / VS Code 終端機）。

🔌 帳號、環境與擴充

指令用法
/login / /logout登入／登出 Anthropic 帳號，或在多個帳號間切換。
/status顯示目前狀態：帳號、模型、API 連線、工作目錄等。
/doctor健康檢查——安裝、認證、MCP 連線有問題先跑這個。
/mcp管理 MCP 伺服器：查看連線狀態、進行 OAuth 認證、檢視各伺服器提供的工具。
/plugin瀏覽、安裝與管理插件（plugins）——一包裝好的指令、skills、MCP 與 hooks。
/fast切換 Fast Mode（更快的輸出速度，適用 Opus 系列模型）。
/help列出目前版本所有可用指令與快捷鍵——這頁的權威來源。
/bug回報問題給 Anthropic，會自動附上對話脈絡。

🛠 開發工作流

指令用法
/review請 Claude 審查 pull request，指出問題與改進建議。
/code-review對目前分支的修改做正確性與品質審查，可指定深度（low～max）。
/security-review對目前分支的修改做安全審查（注入、權限、機密外洩等）。
/pr-comments抓取目前 PR 上的審查留言進對話，直接請 Claude 逐條處理。
/install-github-app安裝 GitHub App，讓你在 PR / issue 留言中 @claude 觸發 Claude 自動工作。
/todos查看 Claude 目前的任務清單與進度。

✨ 自訂你自己的 Slash 指令

任何重複輸入的提示詞都可以做成自訂指令。建一個 Markdown 檔即可：

# .claude/commands/fix-issue.md（專案內共用，會進版控）
# 或 ~/.claude/commands/fix-issue.md（個人全域）
---
description: 修復指定編號的 GitHub issue
---

請依照以下流程修復 issue #$ARGUMENTS：
1. 用 gh issue view $ARGUMENTS 讀取問題描述
2. 找出相關程式碼並修復
3. 撰寫測試驗證
4. 建立 commit，訊息註明 Fixes #$ARGUMENTS

之後輸入 /fix-issue 123，$ARGUMENTS 就會被換成 123。要點：

  • 位置決定範圍：.claude/commands/ 是專案層級（團隊共用）；~/.claude/commands/ 是個人層級（所有專案可用）。
  • 子資料夾即命名空間：.claude/commands/frontend/component.md 會顯示為 /component (project:frontend)。
  • frontmatter 可加設定：description（指令說明）、allowed-tools（限制可用工具）、model（指定模型）。
  • 內容可以動態取材：在指令內容用 !`git status` 可在執行時嵌入 shell 指令輸出，用 @檔名 嵌入檔案內容。
💡 經驗法則：同一段提示打過三次，就值得存成自訂指令；如果還希望 Claude 在情境符合時「自動」套用（不用你打指令），則做成 skill——見進階篇。
